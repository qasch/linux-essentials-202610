# Übungen zu `locate`

## Vorbereitung

Stelle sicher, dass `locate` installiert ist. Wechsle mit `su -` in den Account von `root` und führe folgende Kommandos aus:

```bash
apt update
apt install locate
```

Wechsle nach der Installation mit folgendem Kommando wieder in den Account deines regulären Users:

```bash
exit
```

Prüfe anschließend, welches `locate` installiert wurde:

```bash
locate --version
```

> [!NOTE]
> Unter Linux gibt es mehrere Programme, die `locate` heißen, z. B. das `locate` aus den GNU findutils, `mlocate` und `plocate`. Sie funktionieren sehr ähnlich, unterscheiden sich aber in Details wie Optionen, Ausgabe und Speicherort der Datenbank. Diese Übungen beziehen sich auf das `locate` aus den **GNU findutils**, das mit dem Paket `locate` installiert wird.

## Übung 1: Die erste Suche

1. Suche nach allen Dateien und Verzeichnissen, deren Pfad `bash` enthält.

   Vermutlich bekommst du keine Treffer, sondern eine Fehlermeldung. Lies sie genau:

   - Welche Datei wird vermisst?
   - Was könnte das für eine Datei sein?

2. Wechsle in den Account von `root`, führe dort das Kommando `updatedb` aus und verlasse den `root`-Account wieder. Wiederhole anschließend die Suche.

   > [!NOTE]
   > Warum dieser Schritt nötig ist, findest du in **Übung 2** heraus.

3. Zähle, wie viele Ergebnisse gefunden wurden. Löse die Aufgabe zunächst mithilfe einer Pipe.

4. Schau anschließend in der Manpage von `locate` nach, ob `locate` selbst eine Option besitzt, mit der nur die Anzahl der Treffer ausgegeben wird.

5. Begrenze die Ausgabe auf die ersten 10 Treffer. Löse auch diese Aufgabe zunächst mithilfe einer Pipe.

6. Finde anschließend heraus, ob `locate` selbst eine Option besitzt, mit der die Anzahl der ausgegebenen Treffer begrenzt werden kann.

## Übung 2: Die Datenbank und ihre Aktualität

1. Erstelle eine neue Datei in deinem Home-Verzeichnis:

   ```bash
   touch ~/meine_testdatei.txt
   ```

2. Versuche, die Datei mit `locate` zu finden:

   ```bash
   locate meine_testdatei
   ```

   Die Datei wird nicht gefunden. Warum?

   Lies dazu in der Manpage von `locate` nach, wie dieses Programm arbeitet.

3. Sorge nun dafür, dass `locate` die neu erstellte Datei findet.

4. `locate` durchsucht also nicht bei jeder Suche das Dateisystem, sondern eine Datenbank. Finde heraus, wo diese Datenbank auf deinem System liegt.

   > [!TIP]
   > In der Manpage von `locate` wirst du nicht fündig. Die Datenbank wird von `updatedb` erstellt, also lohnt sich ein Blick in **dessen** Manpage.

5. Lass dir die Datenbankdatei mit `ls -l` anzeigen. Wann wurde sie zuletzt aktualisiert?

## Übung 3: Automatische Aktualisierung der Datenbank

Niemand möchte ständig von Hand `updatedb` ausführen. Das Paket `locate` bringt deshalb ein Skript mit, das die Datenbank täglich automatisch aktualisieren soll.

1. Schau dir an, welche Skripte im Verzeichnis `/etc/cron.daily/` liegen. Welches davon gehört vermutlich zu `locate`?

2. Skripte in diesem Verzeichnis werden vom Dienst `cron` einmal täglich ausgeführt, sofern er installiert ist und läuft. Prüfe, ob das auf deinem System der Fall ist:

   ```bash
   systemctl status cron
   ```

   Was bedeutet das Ergebnis für die Aktualität deiner `locate`-Datenbank?

3. Führe das Skript nun als `root` von Hand aus, genau so, wie `cron` es täglich tun würde:

   ```bash
   /etc/cron.daily/locate
   ```

   Verlasse den `root`-Account wieder und suche erneut nach deiner Testdatei:

   ```bash
   locate meine_testdatei
   ```

4. Wird die Datei noch gefunden? Um das Ergebnis zu erklären, helfen dir:

   - die Ausgabe von `ls -ld ~`
   - die Variable `LOCALUSER` im Skript `/etc/cron.daily/locate` (schau dir das Skript z. B. mit `less` an)

   Unter welchem Benutzer wird das Dateisystem bei der automatischen Aktualisierung durchsucht? Und unter welchem Benutzer, wenn du `updatedb` als `root` von Hand aufrufst?

5. Führe zum Schluss als `root` wieder `updatedb` aus, damit die folgenden Übungen wie erwartet funktionieren.

## Übung 5: Geschwindigkeitsvergleich `locate` vs. `find`

> [!NOTE]
> Mit dem Kommando `time` kann man messen, wie lange ein Kommando für seine Ausführung braucht. Dazu stellt man `time` einfach vor das auszuführende Kommando.
>
> Wir vergleichen `locate` nun mit `find`, einem anderen Kommando zur Suche nach Dateien. `find` schauen wir uns später noch genauer an. Hier kannst du die vorgegebenen Kommandos einfach übernehmen. Die eigentlichen Suchergebnisse interessieren uns nicht, daher leiten wir sie nach `/dev/null` um.

1. Miss die Zeit, die `locate` für die Suche braucht:

   ```bash
   time locate bash > /dev/null
   ```

2. Miss anschließend die Zeit für eine Suche mit `find`, die ausgehend von `/` das komplette Dateisystem durchsucht:

   ```bash
   time find / -name "*bash*" &> /dev/null
   ```

3. Führe das `find`-Kommando ein zweites Mal aus. Was fällt dir bei der benötigten Zeit auf? Hast du eine Vermutung, woran das liegen könnte?

4. Vergleiche nun die **Anzahl** der Treffer:

   ```bash
   locate bash | wc -l
   find / -name "*bash*" 2> /dev/null | wc -l
   ```

   Die Zahlen unterscheiden sich deutlich. Das hat zwei Gründe:

   - Lass dir die Treffer von `locate bash` mit `less` anzeigen. Enthält wirklich jeder Treffer `bash` im **Dateinamen**? Wo genau sucht `locate` nach dem Suchbegriff?
   - Als welcher Benutzer hast du `find` ausgeführt, und als welcher Benutzer wurde die Datenbank erstellt? Was bedeutet das für die Ergebnisse? (Tipp: Lass beim `find`-Kommando die Umleitung `2> /dev/null` testweise weg.)

5. Suche in der Manpage von `locate` nach einer Option, mit der nur der **Dateiname** (der letzte Teil des Pfads, englisch *base name*) durchsucht wird. Vergleiche die Anzahl der Treffer erneut.

6. Beantworte abschließend:

   - Warum ist `locate` normalerweise deutlich schneller?
   - Ist der Geschwindigkeitsvergleich aus Aufgabe 1 und 2 wirklich fair?
   - Welche Nachteile nimmt man für den Geschwindigkeitsvorteil von `locate` in Kauf?

## Übung 7: Suchmuster mit Wildcards

> [!NOTE]
> Für diese Übung brauchst du dein Wissen aus der Übung zu **Globbing und Wildcards**.

### 7.1 Teilstring oder Muster?

1. Vergleiche die Ausgaben der folgenden beiden Kommandos (die Anzahl der Treffer reicht):

   ```bash
   locate .conf
   locate "*.conf"
   ```

2. Schau dir bei der ersten Variante Treffer an, die bei der zweiten fehlen. Was haben sie gemeinsam?

3. Lies in der Manpage von `locate` im Abschnitt **DESCRIPTION** nach: Was ändert sich am Suchverhalten, sobald ein Suchmuster Metazeichen wie `*`, `?` oder `[]` enthält?

### 7.2 Warum die Anführungszeichen?

1. Erstelle in deinem Home-Verzeichnis die Datei `test.conf`, aktualisiere die Datenbank und wechsle in dein Home-Verzeichnis.

2. Vergleiche:

   ```bash
   locate "*.conf"
   locate *.conf
   ```

3. Erkläre den Unterschied. Wer wertet den `*` jeweils aus: die Shell oder `locate`?

   > [!TIP]
   > Lass dir mit `echo locate *.conf` anzeigen, welches Kommando die Shell tatsächlich ausführt.

### 7.3 Suche auf das Home-Verzeichnis einschränken

1. Suche nach Treffern, deren Pfad `bash` enthält, die aber nur ausgegeben werden sollen, wenn sie innerhalb deines Home-Verzeichnisses liegen.

   Löse das Problem zunächst mithilfe einer Pipe und eines weiteren Kommandos.

2. Löse die Aufgabe anschließend nur mit einem geeigneten Suchmuster für `locate`.

   > [!TIP]
   > Die Variable `HOME` enthält den Pfad zu deinem Home-Verzeichnis. Denk an das Ergebnis aus 7.1: Mit Wildcards muss das Muster auf den **gesamten** Pfad passen.

### 7.4 Muster und Dateinamen

1. Suche nach allen Dateien in `/etc`, deren Name auf `.conf` endet:

   ```bash
   locate "/etc/*.conf"
   ```

   Findest du auch Dateien in **Unterverzeichnissen** von `/etc`? Lies in der Manpage nach, wie sich `*` bei `locate` im Unterschied zum Globbing in der Shell gegenüber `/` verhält.

2. Suche mithilfe der Option aus Übung 5.5 nach allen Dateien, deren **Name** mit `bash` beginnt.

3. Erweitere die Suche so, dass auch versteckte Dateien gefunden werden, deren Name mit `.bash` beginnt (z. B. `.bashrc`).

   > [!TIP]
   > `locate` akzeptiert mehrere Suchmuster gleichzeitig.
